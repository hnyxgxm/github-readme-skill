# 图怎么画：画布、字号、字体与体积

[渲染与尺寸](rendering.md) 给的是判据，这一页给做法。每个数字都标了来源：**[实测]** 是自己量出来的，**[官方]** 是平台响应头或文档，**[经验]** 是工程阈值，可以按项目调。

画图的目标不是好看，是在读者那一屏上**能读清、不崩、不太慢**。审美交给审稿人。

## 1. 先定画布，再定字号

首屏图、节标题图、示意图都用同一套画布，读者滚动时不会忽大忽小。

| 用途 | 画布 | 在 838px 正文列里的缩放 |
| --- | --- | --- |
| 首屏图 | `1200 × 300–420` | 69.8% |
| 节标题图 | `1200 × 120–170` | 69.8% |
| 示意图 | `1200 × 320–760` | 69.8% |

用 1200 是为了坐标好算，代价是所有字号都要乘 0.698。不想算换算就直接用 `838` 宽、`1.0` 缩放，所见即所得；用 `1676` 则是 2 倍图，Retina 上更干净，缩放同样是 50%。

**[实测]** 桌面端不管窗口多宽，正文列都是 838px（1280/1440/1920 三档一致），窄屏 390 视口是 324px。所以缩放比例是固定的，不用按视口算。

字号换算：

```text
渲染字号 = 图内字号 × 838 ÷ 画布宽
```

| 画布 1200 上的字号 | 渲染后 | 判断 |
| --- | --- | --- |
| 14 | 9.8px | 手机上不可读 |
| 16 | 11.2px | 低于下限 |
| 18 | 12.6px | 勉强，只适合脚注 |
| 22 | 15.4px | 正文标签的起点 |
| 28 | 19.6px | 小标题 |
| 44 | 30.7px | 主标题 |

**[经验]** 12px 是可读下限，低于它中文在 1x 屏上明显吃力。这条没有做过分组可读性实验，按经验值用。

## 2. 字体只用系统栈

**[官方]** `raw.githubusercontent.com` 的响应头是：

```text
content-security-policy: default-src 'none'; style-src 'unsafe-inline'; sandbox
```

作为 `<img>` 加载的 SVG 是独立文档，受这条 CSP 约束：**除内联样式外，一切外部资源都被拦掉**。`@import` 字体、`@font-face`、外链图片、脚本，全部失效。

**[实测]** 用 CDP 加载一个带 `@import` Google Fonts 的 SVG，网络面板里没有任何 `fonts.googleapis.com` 请求，字体直接回落到本机字体。

后果比"字体不一样"更严重：**按目标字体宽度排好的版会错位**。你数着字符调的行宽，在别人机器上换了字体就溢出框或留下大洞。

所以：

```xml
<text font-family="-apple-system, BlinkMacSystemFont, 'Segoe UI', 'Noto Sans SC', sans-serif">
```

只写系统字体名和通用族。**写完必须在本机实际渲染一次再看宽度**，不要数着字符估算——中英文字宽本来就不同。

## 3. 深浅色：图要自带底

SVG 作为独立文档，**不继承页面的背景色**。没画背景的图，在深色主题下会露出页面底色；如果图里的文字是深灰，就直接消失。

三种做法，从稳到巧：

**A. 不透明背景（最稳）**。铺一个覆盖全画布的 `<rect>`，用中性色或品牌色，文字颜色跟它保证对比。两种主题下表现一致，代价是深色主题里会出现一块亮色。

**B. 跟随主题（推荐，但发布前要看一眼）**。媒体查询在 `<img>` 里是生效的：

```xml
<style>
  .bg { fill: #ffffff; }
  .fg { fill: #111111; }
  @media (prefers-color-scheme: dark) {
    .bg { fill: #0d1117; }
    .fg { fill: #f0f6fc; }
  }
</style>
<rect class="bg" width="1200" height="320"/>
```

**[实测]** 在 Chrome 里用 `Emulation.setEmulatedMedia` 切换配色偏好，同一个 SVG 取到两种背景色：浅色模式 `#ffffff`，深色模式 `#0d1117`。

**这条没有在线上 GitHub 实拍验证过。** 按规范，页面声明 `color-scheme` 会带动媒体查询，而 GitHub 切换主题时正是这么做的；但发布前把页面切到深色亲眼看一次，这一步不能省。

**C. 两张图**。浅色一张、深色一张，用 `<picture>` 切换。GitHub 对 `<picture>` 的支持不稳定，且维护成本翻倍，**不推荐**。

不管用哪种，都给 `<svg>` 加 `<title>` 和 `<desc>`：读屏软件靠它读图，图注的替代文本也靠它。

## 4. 动图：先砍尺寸和帧率

**[实测]** 同一段 6 秒素材（1200×680、30fps），改编码参数后的体积：

| 参数 | 体积 | 相对基准 |
| --- | --- | --- |
| 30fps / 1200 宽 / 默认调色板 | 4844 KB | 100% |
| 15fps / 1200 宽 | 3340 KB | 69% |
| 30fps / 838 宽 | 3137 KB | 65% |
| 15fps / 838 宽 | 2146 KB | 44% |
| 15fps / 838 宽 / `stats_mode=diff` | 2405 KB | 50% |
| 12fps / 838 宽 / `stats_mode=diff` | 2068 KB | 43% |

两个结论：

1. **尺寸和帧率是唯二有效的旋钮**，各自能砍掉约三分之一，两个一起改能到 44%。先把图缩到 838 宽（正文列宽），再降帧率。
2. **`stats_mode=diff` 在这组素材上反而更大**（2146 → 2405 KB）。常见教程推荐它，但这里实测是负收益：它把调色板预算挪给了变化区域，静态区域的渐变抖动变多，反而更占体积。**别人的参数不要直接抄，按自己的素材各跑一遍再选。**

## 5. 不要用 ffmpeg 直接产出发布用的 GIF

**[实测]** 拿一个真实项目已发布的 1500×937、155 帧、3.61 MB 的首屏动图，用 ffmpeg 重编码：

| 做法 | 体积 |
| --- | --- |
| 原文件（发布时已优化过） | **3.61 MB** |
| ffmpeg 缩到 838 宽 | 26.85 MB |
| ffmpeg + `diff_mode=rectangle` | 25.41 MB |
| ffmpeg + 关抖动 | 23.39 MB |
| ffmpeg + 8fps + 关抖动 | 18.83 MB |

**大了 5–7 倍。** ffmpeg 的 `paletteuse` 不做真正的帧间差分压缩，每帧基本都要重画；已发布的 GIF 是经过专门优化器处理过的。

正确顺序是「ffmpeg 出图 → 优化器收尾」，优化器这一环用 gifsicle 或 gifski：

```sh
gifsicle -O3 --lossy=80 --colors 128 in.gif -o out.gif
```

**这一行本仓库没有在 macOS + gifsicle 上实测过**，参数按官方文档给。跑完对比体积和首帧，不满意再调 `--lossy`。

顺带纠正一个流传很广的说法：**平台没有「GIF 必须小于 5MB」的规定**。

**[官方]** GitHub 的文件限制是：50 MiB 起 git 警告，100 MiB 直接阻止，通过网页上传单文件上限 25 MiB。README 图片没有单独的体积规定。

5 MB、2 MB 是**加载预算**，不是平台红线。首屏动图压在 2 MB 内是为了让读者不用等，属于体验取舍，不达标不会报错——但会掉读者。

## 6. 一个真实样本的问题

同一个 1500×937 的动图，在 README 里声明 `width="860"`，实际渲染 838px。

也就是说**录的时候按 1500 宽录的，44% 的像素从来没被显示过**。按第 5 节的表，缩到 838 宽重录能直接省掉这部分，代价为零。

分辨率不是越高越好：**按渲染宽录，不要按屏幕宽录**。

截图的算法不一样：2 倍屏上需要 2 倍像素才清晰，所以表格里 392px 宽的单元格，截图录到 **784px** 宽就够。超过这个数仍然浪费——除非这张图就是要给人点开看原图。

## 7. 交付前自查

- [ ] 画布宽是 1200 / 838 / 1676 之一，不是随手一个数
- [ ] 最小字号换算后 ≥ 12px，正文标签 ≥ 15px
- [ ] `font-family` 只有系统字体和通用族，没有 `@import`、`@font-face`
- [ ] 铺了背景，或者用了媒体查询且**在深色主题下亲眼看**过
- [ ] 有 `<title>` 和 `<desc>`
- [ ] 动图宽 = 渲染宽，帧率 ≤ 15fps
- [ ] 动图体积在 2 MB 附近，超了先砍尺寸再砍帧率
- [ ] 图在 838px 和 324px 两个宽度下都能读

跑 [check-assets.py](../scripts/check-assets.py) 可以自动判掉其中一半（字号、字体、背景、体积、宽高），剩下的要你自己看：

```sh
python3 scripts/check-assets.py README.md
```

它不判好不好看。**能算的交脚本，要判断的交眼睛**，这条线不要混。
