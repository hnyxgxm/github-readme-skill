# 图片与视频：什么时候放、放哪、要不要视频

第 4 步用这份。图片和视频不是写完再补的装饰，是动笔前就要定下来的事：它们占首屏、影响读者往哪看，还决定第二段有没有东西可放。

## 一、三句问完再决定

```
这个项目有能看见的东西吗？
    没有（纯命令行、纯库、纯方法） → 不放内容图，第二段用真实输出或文字
    有 ↓
一张静止的图能不能说清？
    能 → 放一张静态图，位置见第二节
    不能 ↓
非得看到连续动作才懂吗？
    是 → 才考虑动图或视频，规则见第三节
    不是 → 说明你要的不是图，是把那段文字写清楚
```

默认答案是「不放视频，最多一张图」。加一张图之前先说得出「它替读者回答了哪个问题」，说不出就别加。

## 二、什么时候放图片，放在哪

| 情况 | 放什么 | 放第几段 | 理由 |
| --- | --- | --- | --- |
| 有界面、有产物，一眼能看出区别 | 一张真实界面图或前后对照图 | 第二段，紧跟首屏定位 | 接住第一段的承诺，读者不用先信文字 |
| 工具能跑出结果，但没有界面 | 不用图，用一段真实命令输出 | 第二段（文字块） | 截图里没有额外信息，何必放 |
| 某一项功能需要看图才懂 | 一张局部图，配一句说明 | 第五段，放在那一条功能下面 | 证据按功能分置，不堆在开头 |
| 项目是模板、研究、技能包 | 采用之后的实际产物，或基准表 | 第二段 | 光说「效果好」没有可核对的东西 |
| 纯方法、纯教程，没有可看的产物 | 不放；用目录结构和一个完整例子 | 第二段用表格或链接 | 装饰图会让读者误以为有软件可装 |

不允许的位置：

- 首屏连放三张以上。读者还没弄明白这是什么，就先被图推着走。
- 用 Logo、头像、视频封面当主证据。它们是身份材料，不证明项目能做什么。
- 把整个工作台缩成缩略图塞进正文。838px 的正文列下，字根本读不出来，等于没放。
- 文末补一张「感谢关注」之类的装饰图。

每张图都要配两样：**图注**说明这是什么、该看哪里；**替代文本**写出图里的内容，让看不到图的人也能接上上下文。图注已有准确身份，正文里就不要再重复一遍「这不是效果图」这类否定句。

## 三、要不要视频、什么时候用

先说结论：**大多数 README 不需要视频。** 判断只有一条 —— 静止画面说不清、必须看到连续动作才懂，才用。

| 情况 | 用什么 | 说明 |
| --- | --- | --- |
| 一次点击的前后变化，一张对照图就说得清 | 静态图 | 别为「显得高级」上视频 |
| 连续操作、拖拽、动画过渡、状态随时间变化 | 动图（GIF） | 会自动播放，适合短动作；体积大，要压 |
| 需要声音、需要暂停看细节、时长超过十几秒 | 视频（MP4） | 在 GitHub 页面上要点一下才播，不会自动播 |
| 只是想展示界面长什么样 | 静态图 | 视频代价最高、信息密度最低 |

三条硬约束：

1. **关键内容不能只靠画面**。安装命令、版本要求、限制条件、成功标志，必须同时写成文字。读者可能没点开视频，也可能看不到图。
2. **默认不放视频**。要放，在六行结论里写明「静止图说不清哪一步」，并说清放第几段。
3. **视频不能顶替第二段的主证据**。它更适合放在第五段对应功能下面；首屏给一张能立刻看懂的静态图，再链到视频。

### 平台限制（写之前先记住）

| 项 | 限制 | 出处 |
| --- | --- | --- |
| 单个图片、动图 | 不超过 10 MB | GitHub 官方「Attaching files」 |
| 单个视频 | 不超过 10 MB | 同上 |
| 支持的格式 | PNG、GIF、JPEG、SVG；视频 MP4、MOV、WEBM | 同上 |
| 视频编码 | 建议 H.264，兼容性最好 | 同上 |
| README 正文 | 超过 500 KiB 会被截断 | GitHub 官方「About READMEs」 |
| MP4 是否自动播放 | 官方没写；第三方实测是「要点一下才播，声音可用」 | 见文末出处，属实测结论不是官方承诺 |
| GIF 是否自动播放 | 会自动播放 | 同上，普遍实测现象 |

动图做法（尺寸、帧率、压缩参数）见[图怎么画](visual-craft.md)。那组参数要 `ffmpeg` 和 `gifsicle` 1.95 以上；机器上没有就只给静态图建议，并说明这一档没验，不要拿参数表冒充量过。列宽、字号换算和并排图的可用宽度见[渲染与尺寸](rendering.md)。

## 四、按项目类别的默认决定

和第 4 步的六行结论对得上，可直接抄：

| 类别 | 图片 | 视频 | 位置 |
| --- | --- | --- | --- |
| 工具类（命令行） | 通常不放；第二段用命令输出 | 不放 | — |
| 工具类（桌面软件） | 一张真实界面 | 只有拖拽类操作才用动图 | 图在第二段，动图在第五段 |
| 教程或方法类 | 学完的产物图，或干脆不放 | 不放 | 图在第二段 |
| 网站或在线服务 | 一张真实界面 | 只有连续交互才用 | 图在第二段，接在线入口 |
| 库或开发包 | 通常不放；第二段用最小调用 | 不放 | — |
| 其他（模板／研究／技能） | 采用后的实际产物或基准表 | 不放 | 第二段 |

这张表是默认，不是规定。项目里真有一段必须看动画才懂的操作，就按第三节的规矩加，并在结论里写明理由。

## 五、常见错法

| 症状 | 原因 | 怎么改 |
| --- | --- | --- |
| 首屏三张图，还是不知道怎么开始 | 把「有图」当「有证据」 | 只留一张能说明区别的，安装提到前 25 行 |
| 放了视频，安装命令只出现在画面里 | 关键内容只靠画面 | 命令写成可复制的文字块 |
| 动图十几 MB，页面加载很久 | 没压就传；正文还有 500 KiB 截断风险 | 按 visual-craft.md 压，或换成一张静态图加文字 |
| 图里字小到读不出 | 把整页截图缩小塞进来 | 重画，或改成能点开的完整页面链接 |
| 用 Logo 当第二段主证据 | 分不清身份材料和证据 | 换成真实输出、界面或产物 |
| 本地预览里视频能自动播，线上不动 | 把本地浏览器行为当成 GitHub 行为 | 按上表的平台限制写，线上页面实拍确认 |
