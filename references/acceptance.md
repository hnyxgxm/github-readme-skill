# 验收：这篇首页能不能用

判断标准是读者能否据此决定要不要试、并完成第一次使用。章节齐全、字数减少、链接全部通过、模型自评高分，都不能单独证明写得好。

本页所有条目都是必过的门：成稿后逐条对照回答「过 / 不过 / 不适用（附原因）」，一条不过先改再走下一条，交付时报告核对结果。

## 1. 先过形态门

问一句：除了这份 README，读者还有别处可去吗？依据是有没有独立文档站或仓库内文档目录，不是正文里恰好写没写链接。

- **路由页**：细节已在文档站，README 只留定位、入口、文档链接、许可；安装步骤不在两处各写一遍。
- **中间态**：仓库内有 `docs/` 或 `references/`，README 保留“不读文档也能试一次”的部分。
- **手册**：没有别处可去，安装、首次结果、边界、常见问题都在本页，不能只写定位加链接。

形态写错时先改结构，不补句子。有文档站却抄全量参数，注定过期；没有文档站却只给链接，读者无处可去。

## 2. 事实与边界

- 对照当前入口、发布物和许可证核实名称、命令、依赖、平台、收费、权限及数据行为。没有依据的效果、性能、兼容和用户认可不写。
- 核对图像、示例身份与来源。教学、原型、实际产品、实验结果不能互换；图注说了“教学示范”，正文就不能暗示效果提升。
- 检查新增与原有链接、图片、文件大小写及锚点；扫描本轮相关的所有语言版本，不只检查根 README。
- 检查变更中是否留下内部路径、凭据、开发日志或未替换占位说明。新增文件在本地存在不等于已经发布。
- 没有擅自修改许可、安装配置、产品行为、部署或远端状态。

## 3. 按分支走通

扮演每个承诺支持的平台或客户端读者，只使用文中步骤及明确链接的详情：

1. 知道环境要求、获取哪个交付物、在哪个目录或宿主执行。
2. 能安装、启用并完成一条具体任务，知道预期结果。
3. 不需要另搜目的目录、包名、参数或权限；“按工具说明”没有完成这一步。
4. 已有安装、覆盖或危险写入有适当提示；必要风险没有藏在折叠内容之后。
5. 更新/卸载若列出，与安装的渠道、名称和作用域一致；互斥动作没有混成一个可复制的命令块。
6. 核心功能或指令的语言限制在安装、使用前已说明，而非到文末才发现。
7. 多个客户端共用同一安装器时，只有一条命令，客户端差异以三行同构短列表（或参数表）列出，每行只换目标名、目录或启用方式；没有把同一命令改写成插件市场、ZIP 上传等并列渠道。
8. 原生入口（上传、插件市场）只作为缺运行环境时的备选，写明它替代什么；不是与统一路径并列的第三种体系。
9. README 平台做不出水平标签：没有用纵向折叠假装分渠道，也没有把同一条命令折成三块冒充三种方法。

实际执行前判断副作用，优先隔离目录。分别报告官方核实、实际运行与未验证；没有安装权限时不要在真实用户配置里试命令。无可靠资料的路径要标明缺口，不能以减少支持范围偷偷消掉用户需求。

## 4. 首屏与证据

首屏行数与徽章个数的口径以 SKILL.md §4 为唯一出处，本页只列检查项，不重复数字。

把首屏交给没读过项目的人，要求回答三个问题并指出位置：

- 这是什么？用一个具体任务说明为什么值得试。
- 凭什么相信？证据类型是否匹配交付物（基准表、界面、调用输出、复现链、真实命令），而不是一张装饰图。
- 下一步点哪里？安装入口在首屏或前三节内；安装排在第 4 节之后时，首屏必须有 quick links 或锚点。

再看结构：

- 首屏内能读到名称、一句定位、动作或证据；粗体、图注、徽章不争抢重心，没有全粗体长介绍或全斜体长图注。
- 每一块用的形状是读者看懂最快的那种：表格只放短项比较，步骤用有序列表，因果在段落里，证据用图片，可选分支才折叠。换成别的形状读者会看得更快，这块的形状就选错了。
- 徽章个数按 §4，每个都要能帮助判断（版本、CI、许可、平台、下载量）；0 个也可以，但没有纯粹的装饰墙。
- 主证据只有一份，其余按功能分置；证据不足时承诺已收窄，而不是用形容词补位。
- 图注说明“这是什么、看什么”，不是效果证明；教学示范、原型等身份词准确。

## 5. 双语逐项对照

先判断本次是否需要双语；不把语言数当质量指标。需要时两版必须有：

- 相同位置、顺序稳定的语言互链，保留已有根语言和命名约定。
- 对应的用途、安装分支、环境要求、首次任务、限制、许可和帮助路径。
- 一致的命令、包名、参数、文件路径及链接目标；本地锚点随各语言标题正确变化。
- 翻译后的图注、替代文本、任务示例和折叠标签，而不只是翻译前两段。
- 自然表达，不强化事实；明确区分 README 语言与产品/深层资料语言。

对局部修订检查相关事实一致即可，不借机迁移语言文件或重构全文。

## 6. 阅读与渲染

先跑两个脚本，把能算的算掉，再拿眼睛看剩下的。脚本在技能目录里，工作目录是被审的仓库，所以按绝对路径调用：

```sh
SKILL=~/.claude/skills/github-readme-skill          # 换成实际安装位置
python3 "$SKILL/scripts/check-assets.py" README.md README.en.md      # 图与文件链接会不会崩
python3 "$SKILL/scripts/check-text.py" README.md README.en.md --pair --terms "$SKILL/references/terms.txt"   # 结构、双语、术语
```

直接写 `scripts/check-assets.py` 只在本仓库内成立；装成 Skill 后目标仓库里没有这个文件，会直接报 No such file。两个脚本只依赖 python3 标准库（3.8 以上），不需要 pip 装东西。

脚本只判机械项：图不存在、大小写不符、字号换算后过小、引用了会被 CSP 拦掉的远程字体、缺 viewBox、超出正文列宽、Markdown 与 HTML 写的文件链接指向不存在的路径、首屏行数与首屏有没有动作或证据、徽章数量、H1 数量、失效锚点、两版章节数不对、术语漂移。**脚本通过不等于可以交付**，下面这些它一项都判不了。

换平台（GitLab、Bitbucket、npm、PyPI）要重新量列宽，用 `--column-width` / `--table-width` 覆盖脚本里的 GitHub 实测值。

打开真实目标渲染，或诚实标注的本地近似预览。在常规阅读宽度与约 390px 窄屏检查首屏、安装、示例、文末：

- 一份文档只有一个 H1；H2/H3 语义清楚，导航落点正确。
- 标题扫读能找到自己的安装入口和最小用法；需要的前提与影响采用的限制在相应位置。
- 图片加载且关键内容可读；复杂截图在窄屏允许点击原图查看，不伪装成可用界面。
- 图在浅色与深色两套主题下都能读；深色下不出现一块刺眼的白板，也不出现消失的文字。
- 长命令在代码区滚动，不撑出整个页面；表格没有迫使读者横移才能读完每一段说明。
- 实际点击语言切换、锚点、图片和折叠；键盘可达，必要内容未被 HTML 渲染吞掉。
- 预览不依赖私有样式美化一个在 GitHub 上失效的排版。不加任意 CSS 再称 GitHub 页面验收。
- 同一个概念在 SKILL.md、references、README 和脚本输出里用同一个词；换了词就是换了概念，读者要重新学一遍。

不能渲染时报告未完成，不把源码检查当读图。检查通过只是底线；最终判断还要说明哪个具体组织关系让页面好读，而不是宣称客观“满分”。

### 没有浏览器时怎么降级

多数 Agent 运行时没有浏览器，也没有 CDP。这时不要只写一句“渲染未完成”就收口，按下面三档退，并在交付说明里写明用了哪一档：

1. **真实渲染**（首选）：目标平台的线上页面，或按同一套 CSS 复现的本地预览。
2. **静态估算**：按 838px 正文列、392px 表格单元格换算，核对图内最小字号、声明宽度和固有宽是否够；`check-assets.py` 已经把这一档能算的算完了，剩下的是读代码里的 `<style>` 和窄屏媒体查询。
3. **纯源码**：只做结构和链接检查，明确写“未做渲染验收”。

第三档仍然是缺口，不能当通过。降级的用途是把“没条件做”和“做了没过”分开，不是把缺口写成合格。

## 7. 收口口径

事实与操作门通过、渲染无阻断、读者能复述项目区别并完成对应路径，才可以交付。仍有未知分支、未渲染或未实测时，在交付说明里列出具体缺口；不用“测试通过”替代，也不用删除用户需求来显得完成。
